## 2. 不可协商的规则

| # | 规则 | 说明 |
|---|------|------|
| R1 | **一个修复一个 commit** | 每次修复后立即 `git add` + `git commit`，message 写清问题与修复。**严禁**用 `git checkout -- .` / `git restore .` 之类会还原全部改动的命令。 |
| R2 | **诚实** | 不许假装修好了。不许写 "TODO" 敷衍。不许把测试改弱来让测试通过。每条发现都要有证据（文件+行号）。 |
| R3 | **必须验证** | 改动后跑 `pnpm check`（tsc）、`pnpm test`（vitest）、相关 lint/build。改坏了就修好再提交。 |
| R4 | **子代理管理** | 可以并行开子代理；若某子代理长时间无进展/卡死/重复劳动 → 主动 `interrupt_agent` 停掉它。 |
| R5 | **联网自由** | 需要搜索/查文档/装依赖 → 直接做，不询问。 |
| R6 | **循环到底** | 只有当"遍历全部代码 + 枚举全部功能 + 修完所有已发现问题 + 复检"都完成，才可宣告目标达成。 |

## 4. 审计方法论（每轮都要重跑）

1. **建立功能清单**：从 `App.tsx` 路由 + `server/routers.ts` 端点 + `shared/` 枚举全部用户可见功能。
2. **逐功能深审**：前端页面/组件 → 对应后端端点 → DB 字段 → i18n key，四层对齐检查。
3. **静态检查**：`pnpm check`、`pnpm test`、`pnpm build`。
4. **UI/UX 扫描**：空状态、加载态、错误态、禁用态、键盘可达性、响应式、深浅色、i18n 漏译、
   长文本溢出、触达区尺寸、焦点陷阱、`aria` 标注。
5. **边界与竞态**：并发、分页、越权、时区、时序（时间戳单位 ms/s）、空数组、空字符串。
6. **记录 → 修复 → commit → 继续**。

- **一次模型失败看起来像一句空回复**：tRPC 的几个入口和微信/飞书都没读 `error` 事件 →
  现在会报错，渠道会告诉用户「请再发一次」。
- **模型/provider 的原始报错文本被直接写给浏览器** → 只告诉用户发生了什么。
- **「分发」把上传的聊天记录发到了运营方的账号**（用户自己配了密钥也没用）→ 改用用户自己的 provider。
- **记忆检索的关键词覆盖率算错了分母**：长记忆几乎永远检索不到（上传文件的摘要永远不被检索）。
- **用户钉住的记忆会被分数更高的挤掉**。
- **一封信可能被投递了却没有进入对话**（两次写入没有事务）→ 改成一个事务。
- **被认领的信在进程死掉后永远丢在「已回答但没有回答」的状态** → 认领改成时间戳，过期可以重认。
- **大厅首屏对每个分身做三次数据库往返**；**时间线对每个分身查一次**；**采集预览把整份历史读进来只看 50 行**；
  **上传页把每份文件 50 万字的提取文本拉回浏览器**；**第一次记忆提取把全部历史读进内存**。
- **周年的日期按服务器时区算**；**分手日期记成 UTC 那天**；**心情/情绪的窗口用的是服务器日历**；
  **统计页一天里的图表有两个日历**；**大厅「今天的对话」用的是服务器午夜**。
- **导出没有上限**（单分身的四个列表）；**设置默认模型没有生效也报成功**；**六个删除按钮没删掉也报成功**；
  **清理对话后计数没归零**；**蒸馏失败后分身永远卡在「分析中」**；**来源列表把数据库错误显示成「没有授权来源」**。
- 界面：**危机卡片关不掉**；**离开页面时回复还在跑**；**三个页面的错误页没有返回按钮**；
  **「把这些带走」打开了错误的标签页**；**五个按钮在双击时发两次请求**；**普通记忆被当成「重要时刻」**；
  **`<ol>` 里塞了 `<div>`**；**问卷的存档形状不对会崩**；**列表弹窗的可访问名和标题不一致**。

### 2026-10-27 — Round 1 第十一批修复（第四轮子代理审计）

第四轮有三个子代理，分别查了「聊天/调度/安全层」、「整个使用旅程（头十分钟、应用的承诺、毕业、两边、自托管承诺）」
和「前端」。这一批修的是**会丢数据、会说假话、会让人无话可说**级别的问题：

- **「重新生成」在分身的对话锁外面删对话**：删除发生在拿到锁之前，所以它能删掉正在飞行的
  那一轮刚存下的用户消息，然后那一轮把助手的回复存下来——留下一条没有用户消息的助手消息。
  现在整段重新生成都在锁里。
- **摘要只从滑动的窗口重建**：最老的那部分摘要内容**永远丢了**——新摘要只覆盖最近一百八十条消息，
  一段关系的前六十轮在任何摘要里都不存在。分身一次忘掉两句话地忘记故事的开头。
  现在上一次的摘要替它已经覆盖的部分说话，窗口只往后长。
- **摘要的节流从来没生效过**：它把摘要**没有**覆盖的二十来条也算进去了，所以计数永远超过阈值，
  长对话每一轮都付一次摘要的钱。
- **语音消息从来没被听过**：录音存下来之后，模型只拿到了**时长**和一个"猜猜他说了什么"的提示词。
  猜出来的话显示给用户当作他自己的话，存成他自己的话，分身还热情地回应它。
  现在录音走 provider 的语音转写服务；听不见的 provider 会说听不见，用户也会被告知没听懂。
- **毕业了的人还在写信**：毕业把分身设为 asleep，聊天那侧会拒绝跟睡着的分身说话；
  信那侧不会——所以告别的**前一天**写下的信，在告别**之后**一天被回答了，用的是分身的口吻。
- **两个渠道都能在界面上绑定了**：提示用户"去设置里选一个分身"的机器人，和一个
  **只有已经绑定了才渲染**的选择器——所以永远没有东西可选，渠道永远答不了话。
  微信现在登录后就能选分身；飞书有了渠道级的默认分身。
- **朗读把回复发给了微软**：这是整个应用**唯一**会离开这台机器的东西，而应用自己的承诺是数据不出机器。
  现在可以关掉（`TTS_ENABLED=false`），关掉后界面上不再有朗读按钮，
  并且那个写着"模型是唯一一处会把内容交出去的地方"的板块现在说的是实话。
- **界面显示的是错误代码**：不带 message 的 `TRPCError` 会被 tRPC 填上**代码本身**当消息，
  所以错误页上写着 "NOT_FOUND"，每个 toast 也是。
- **【关系阶段】永远是"还在互相试探"**：那一段来自一个**没有任何代码会写**的字段，
  所以每一个分身都被告知自己还在试探——包括那个刚刚分手的。
- **用量限制用了三个不同的日历**：起始是服务器的午夜，按天分组用的是服务器那天，
  查的时候用的却是 **UTC** 日期。于是最后那半天被丢掉，其余每天都在错误的键下被查到。
- **毕业的两个入口用了两个日历**：网页读情绪趋势用用户的时区，渠道读用服务器的。
- **"已配置"标签说的是服务器不是你**：标签来自服务器的环境，所以安装方有密钥就写"已配置"，
  而用户自己刚填进去的密钥写"未配置"。用户自己的配置表**没有任何地方读**。
- **采集的文件有四个之一会被拒**：选择器给五个扩展名，全都按"纯文本"发出去，而服务端只收 `.txt`。
- **请求失败被渲染成"你什么都没有"**：微信绑定、采集任务、模板、渠道、来源——都是关于用户自己数据的假话。
- **前端还有**：设置页改一个东西会抹掉另一个（正在打的字）；微规则保存失败会带走刚写的规则；
  "待办清单"永远不会刷新；蒸馏预设不会被记住；四种调用没带语言（英文界面里出中文）；

  微信状态每三秒轮询一次；提醒被投递了却报告成"没投递"。

### 2026-10-27 — Round 1 第十二批修复（第五轮子代理审计）

这一轮有两个子代理：一个查「采集器 + 技能引擎」，一个查「日记 / 导出 / 模板 / 引导 / 上传 / 毕业 / 分身资料 / 文案」。
这一批修的是**会跨用户泄漏数据、会说假话、会让服务器卡死**级别的问题（38 个提交）：

- **采集用的是机器上那份凭据**：凭据的最后一份来源是 `~/.colleague-skill/<source>_config.json`——
  那里面是**在这台机器上做过 `--setup` 的人**的凭据。于是从没授权过任何来源的用户也能跑采集，
  而采集是**以运维的身份**跑的，运维的聊天记录被导进了**用户自己的分身**。
  这和之前修掉的「共享槽位」是同一个泄漏，只是"另一个人"换成了运维。现在只有两个来源：用户自己存的那份，和明确传入的那份。
- **钉钉采集的是运维的聊天记录**：钉钉没有历史接口，只能用浏览器抓，而浏览器里**登录状态就是凭据**。
  采集器原来会回落到机器自己的 Chrome profile——运维的、登着钉钉的那个。现在必须指名一个 profile。
- **凭据文件全世界可读**：`--setup` 写出的 token 是 0644，也就是**本机每一个用户**都能读。改成 0600。
- **采集的时间戳是机器的时区**：采集器把 epoch 转成挂钟，用的是**服务器**的时区；
  服务端再按**读者**的时区读回来，于是服务器在别的国家时每条消息都差几个小时。读者时区现在传给采集器。
- **取消是假的**：AbortController 在两次 await **之后**才登记，所以那个窗口里来的取消被静默忽略，
  采集继续跑最多三十分钟并把消息导进去——而调用方被告知"取消成功"。
- **只能杀掉直接子进程**：钉钉采集驱动的 Chromium 是孙进程，超时和取消之后它还活着。现在整个进程组一起停。
- **队列是全局的**：一个用户排满二十个采集，别人的采集就在后面等几十分钟。每个用户现在有自己的份额。
- **任务状态会乱序落库**：每次进度变化都发一次不等待、不串行的写，"运行中 10%" 可能落在"已完成 100%" 后面。
- **授权失败却说成功**：存储失败被吞掉，界面显示"已授权"，而凭据只在内存里，下一次采集就没有凭据了。
- **导入是分片写的、失败被吞**：第七片失败时前面一千四百条已经提交，任务却报"完成"。
- **微规则两次运行互相覆盖**：挖掘和保存都是"读—改—写"，两个标签页同时跑，后一个的写把前一个的结果抹掉了。
- **微规则挖掘会卡死服务器**：候选上限是**按说话人**算的，而两两比较是平方级的——群聊五十个人就是四百万次编辑距离，
  在事件循环里跑，整个服务器好几分钟不响应。现在说话人共享一份预算。
- **每次蒸馏都往运维家里装东西**：技能写手默认把生成物装进 `~/.claude/skills`，而子进程环境是剥干净的，
  连关掉它的变量都没法从 `.env` 传。现在不装了。
- **上传的素材永远不变成记忆**：蒸馏写出了性格和规则，而**具体的事**（生日、纪念日、去过的地方）留在了上传文件里。
  于是用户为了填满记忆面板而做的那次上传，记忆面板是空的。
- **聊天记录能关掉素材的围栏**：围栏标记是固定字符串，于是一份碰巧含有 `<<<END MATERIAL>>>` 的聊天记录
  提前关掉了围栏，后面的内容被当成指令读。现在标记带随机量。
- **应用承诺了它做不到的事**：上传页写着"不会被分享给任何第三方"，同意框写着"不会发给任何人"——
  而素材**确实**交给了模型（用户配置的服务商，或者用户没配置时这个实例自己的服务商）。
- **保留的 HTML 导出丢了最新的日记**，而 Markdown 导出把心情和事件**打印成内部代码**（`great`、`breakup`）。
- **日记的日历让你写还没到的日子**，而服务端一律拒绝；中文日记**从来没有**彩色的情绪标签。
- **导出的模板失败时什么都没有**：没有文件、没有提示、没有错误。
- **蒸馏预设的键盘焦点一按就丢**：保存期间整组按钮被 `disabled`，而 disabled 的按钮留不住焦点——
  于是箭头键（键盘用户唯一能走到别的预设的方式）第一次按完就失效了。
- **三十五个文案键没人读**，而**本该发现这件事的测试是瞎的**：它用子串匹配，
  所以一个键只要是另一个键的前缀就算"被读过"。

### 2026-10-27 — Round 1 第十三批修复（第六轮子代理审计：聊天 / 渠道 / 安全与统计）

这一轮有三个子代理：一个查**聊天**，一个查**渠道与调度**，一个查**安全层与统计**。
这一批修的是**会在最要紧的时候沉默、会说假话、会吞掉用户写的东西**级别的问题（32 个提交）：

**聊天**
- **停止生成会把半句回答扔掉**：客户端留着，**记录里没有**——于是下一次轮询把它从屏幕上抹了。
  用户按下停止，看到自己的问题和半个回答，二十秒后两个都没了。现在半个回答会存下来，用户自己那句话也留着
  （他停的是**回答**，不是自己说的话）。
- **被拒的消息就没了**：输入框在请求之前就清空了，而最常见的失败恰恰是用户不小心撞上的那个
  （限流，"你发得太快"）。于是写完、发出、被拒、再写一遍。现在文字回到输入框，没存下来的气泡也拿走。
- **重新生成会把后面的话一起删掉**：服务端删的是这一轮**以及它之后的一切**，包括用户自己写的那些，而且无法恢复。
  应用里别的破坏性操作都会先问一句，只有这个不问——而按钮自己的说明写的是"替换当前这一轮"。现在会问，并说清要删几条。
- **手机上输入框只有两三个字宽**：「正在回复……」和「对方那边已经是深夜了」是输入框的**同级 flex 项**，
  把宽度从这一行里拿走了。375 像素的屏幕上输入框被挤成两三个字符——恰好是在对方 abroad 睡着的时候。
- **换分身时上一个分身的什么都还在**：路由是同一条，组件被复用，草稿、危机卡片、对话、"加载更早"的按钮全留着。
- **危机卡片在备用路径上不出现**：图片和语音路径有，流式路径有，备用路径没有——最要紧的那一刻，界面什么都不说。
- **英文用户的照片被中文回答**：图片和语音没有带语言，服务端默认中文——连危机回应都是中文的。
- **重新生成一条主动消息会说"找不到这条消息"**：往前找问题只找**紧挨着的那一条**，而主动消息前面没有用户的话。
- **连接断了，回答会一直转下去**：流在没有 `done` 的情况下结束（连接断、代理掐了、body 被截断），
  气泡就一直显示"正在生成"，整个会话都在，而且没有东西可按。
- **一个失败被渲染成"你什么都没有"**：记忆面板说"你还没有记忆"（用户于是又添加了一遍他明明有的记忆），
  情绪报告说"再聊几天就有数据了"（用户于是去聊天换一张永远不会来的图）。
- **提取记忆说"0 条"却不说为什么**：没提取到新的、模型的回答读不出来、还是早就记过了——三件事一个提示。
- **第五条以后的记忆被悄悄扔掉**：提示词问的是"最多五条"，但同样的上限又套在了**模型的回答**上，
  所以回答了八条的话，最后三条就无声地没了。
- **提取失败每轮都花一次模型调用**：只有读懂答案才推进窗口，于是读不懂就每一轮再付一次钱。
- **"加载更早"把读者甩到了别处**：旧消息加在列表**顶上**，眼睛底下的内容整体下移。
- **场景标签是旧的**（场景存在分身身上，界面不重新读），**失败一声不吭**；**心情标签在写失败时照样变**。
- **网络断了说分身没了**：任何失败都渲染成 404。
- **朗读按钮在它必然失败的时候也摆在那里**（查询还在路上、或查询失败了的时候）。
- **消息列表没有 live region**：屏幕阅读器从不知道对方回答了。

**渠道（微信 / 飞书）**
- **微信一批消息被乱序回答**：代码里写着"同一个会话的消息顺序处理"，而实际上全部并发启动——
  用户连发两条就可能先收到第二条的回答；"/毕业"更糟：同一批里两条就是两次毕业。
- **飞书还没连上就说"连上了"**：`start` 只是**开始**就返回，不等 socket，也从不失败；
  而 App ID 不合法时 SDK 直接返回、不连——界面说"已连接"，背后什么都没有。
- **飞书拒收的消息被记成"已送达"**：SDK 的 `create` 是把 code 放在返回值里，不是抛异常。
- **飞书重投的消息被回答了两次**：那个守卫写了，从来没被调用过。
- **切分身把英文用户变回中文**：语言是从整行文字里猜的，于是 `/use 小B` 是中文——**因为分身的名字是中文**。
- **微信的命令不看用户的语言设置**，只看这句话里有没有汉字。

**安全层与统计**
- **一次数据库抖动会毁掉一个已经写好的回答**：安全层的评估跑在**回答写好之后、存进去之前**，而且没有保护。
- **安全层一天说十五遍同一句话**：它的条件整天都成立（"超过五条"对第六条和之后每一条都成立）。
  于是每条消息都带一遍同样的关心话、弹一次同样的窗、记一行同样的记录——
  而透明度面板只显示最新二十行，于是二十行一模一样，把真正的那一行挤了出去。
- **危机检测漏掉了最常见的说法**：「我不活了」「我要去死」「撑不住了」「I don't want to be here」……
  逐条验过，一条都不触发。而"心情打卡"的备注和"关系时间线"的文字**根本没人扫**——
  用户在"今天怎么样"里写下的那句话，从来没有被危机检测读过。
- **统计的窗口是 30 天却画出 31 根柱子**：窗口是一个绝对时刻，而行是按用户的日分桶的。
- **图表跨过用户不在的日子连线**：没有行的日子不在序列里，折线把它们连了起来。
- **图表把分身的回复也算成用户的**：分身总是几秒内就回，所以每个时段看起来都很忙，
  而且和只算用户发言的安全计数器对不上。
- **"日均消息"是按用户**在的日子**算的**：三十天里的五天聊了一百条，显示成"每天二十条"。
- **跨夏令时的日子被算错了**（实测）：日列用的是**固定**的偏移，而查找用的是**那一天**的偏移——
  于是序列在换季的另一侧每天悄悄丢掉一小时。
- **评估结果没有日期**：六个月前的一次评估和今天早上的一次长得一模一样。

## 第十六批（交接时已完成的部分；余下的清单见 `docs/HANDOFF.md`）

这一批的来源：三个子代理各自审了一片（调度与扫描、采集器与渠道、共享逻辑与 prompt），
报告里能复现的都复现了，能证明的都补了测试。

**最严重的几个：**

- **主动消息每分钟发一条，永远不停**：静默的起点读的是「用户最后说话的列」，而写入的是**另一列**，
  所以被测度的时间从不移动，截止时间一直停在过去，下一分钟又到点了——**每分钟一次模型调用、一次新消息**。
  规则被破掉的那一条，正是购买时写明的那一条：**app 不得比用户买的窗口更频繁地先开口**。
  现在这个窗口从两者中**较晚**的那个算起：用户最后一句话，和 app 自己最后一句话。
- **图片根本到不了模型**：存下来的是 `/uploads/chat/1/2/x.png`——一个**没有主机名**的路径。
  OpenAI 回答 "Invalid image URL"，整个轮次失败；本地模型则悄悄把图丢掉，
  分身**装作没看见**。现在把字节内联（data URL）——对所有 provider 都一样，
  不需要公网主机名（局域网里的自部署应用根本没有），而且图片不必上公网。
- **告别信忽略关系的现状**：对话是从关系事件里解出阶段再交给 prompt 的，信**没有**，
  于是回落到默认值「你们还在互相试探」——**已经分手的人**，收到的是一封新关系语气的告别信。
- **五句互不相干的话被当成告别信呈现**：第二遍要的是 JSON（信、保留的句子、删掉的句子）；
  模型用散文回答时答案切不开，于是用了原始候选句，**而这次运行报告自己是「成功」**。
  「这封信其实就是原始候选句」的标记，只加在了需要它的两条路中的一条上。
- **飞书采集器的凭据被飞书频道的凭据覆盖**：同一份密钥，两种叫法
  （频道叫 `appId`/`appSecret`，采集器读 `app_id`/`app_secret`）。
  频道把自己的那份盖上去，采集器就什么也读不到——**用户刚授权完，采集立刻失败**；
  反过来，只设过频道的用户**永远采不了**。密钥仍然只存一份，只是**按读它的人的语言存**。
- **飞书拒绝的消息被报成「已送达」**：SDK 对业务错误不抛异常，只在 body 里放一个 `code`。
  入站的发信一直会检查它，**出站的没有**——而三个调用方都用「有没有抛异常」当送达判据：
  主动消息被标记成已发（**还把时钟推进了**，于是永远不再重试），提醒的占坑被保留、直接消失，
  app 告诉用户「已经通知你了」。
- **采集器什么都没找到，却报成功**：采集器把原因写在 transcript 里
  （「bot 不在群里」「Playwright 没装」「没登录」），而服务端**先读 JSON、从不打开 transcript**。
  于是运行是「成功、0 条消息、没错」，分身接着**从空无一物里蒸馏**，真正的原因 nowhere。
- **导出日期仍是 UTC**：上海凌晨两点的信，导出成了**前一天**。
  而且——**之前那个声称修好的提交其实没生效**（脚本在写文件之前断言失败，提交只带走了另一半改动）。
  这一条是翻旧账翻出来的，所以现在每个修复都要**对着旧代码跑一遍测试**，确认它真的会红。
- **失败的请求被渲染成「你什么都没有」**：大厅、微规则、便签、评估、模型设置、频道面板，
  以及**整个会话历史**——一次失败的网络抖动，用户看到的是一个**空白的对话**，

  现在**文件里写着缺了什么，屏幕上也说**。
- **Redis 的退出钩子抢先结束了进程**（`5142a5d`）：它收到 SIGTERM 就 `process.exit(0)`。
  Redis 是很早就连上的（调度器要用），所以这个钩子**注册在服务端的之前**——
  于是 HTTP 服务还在服务、通道还连着、飞行中的请求还在跑，进程就被杀了。
  反过来也一样：服务端的关停是异步的，第二个钩子在第一个还在停调度器时就结束了进程。
- **桌面端构建悄悄放过了一个坏包**（`f5271ee`）：PostgreSQL 的拷贝每一处失败都被
  `|| true` 吞掉——构建继续、dmg 照样做出来，然后**在用户自己的机器上**、
  第一次启动时失败，而失败信息跟构建**没有任何关系**。
  那些文件正是 `initdb` 要读的（时区、locale、引导文件）；没有它们，
  打包出来的 app **连自己的数据库都建不起来**。
- **Windows 的冒烟测试永远不会让发布变红**（`7c446f2`）：`continue-on-error: true`
  让那一步是绿的、于是发布是绿的，**而它指向的那个 app 起不来**。
  「坏包也先发出去」是可以商量的政策；**悄悄的失败**不是。
- **「这个分身正在蒸馏中」的闸门十分钟后就失效了**（`aca412c`）：闸门读这一行的
  `updatedAt` 判断第一个进程是不是还活着，而 **`updatedAt` 从来没被写过**——
  它一直停在**创建**的那一刻。名人档要做十五次模型调用，很容易超过十分钟：
  于是用户再点一次「导入到分身」，被告知**已经开始了**，而什么都没发生。

**还有一批「界面在说谎」：**

- 日记页在列表还在路上的时候说「你还没有分身」（`94cac76`）；
- 搜索失败时说「什么也没找到」（`b3ed133`）——用户搜的是自己写过的东西；
- 保真面板请求失败时说「还没有测过」（`b1534c0`）；
- 信件翻页时**同一封信出现两次**，或者**一封信永远消失**（`6b5e824`）——
  写下或删掉一封，最新的一页会挪位，而更早的几页还指着旧的边界；
- 「稍后再说」的便条只给二十条、剩下的不吭声（`efb0d07`）；
- 安全面板「再看更多」点到两百条以上会把整个记录**清空**（`fb12477`）——
  服务端不接受两百以上的 limit，客户端一直加，于是请求自己校验失败，
  列表变空、按钮也没了，界面告诉用户「这段记录读不出来」；
- 档案页在英文界面里印着中文的依恋类型和爱的语言（`6793650`）；
- 英文界面问「要删掉『raining、rain』这条规则吗」（`3bf7a7b`）；
- 离线页和桌面图标只有中文（`ad4ee15`）；
- 时区同步失败之后**再也没试过**（`2bdf1b6`）——代码里写着「试几次」，
  实际上第一次失败就把闸门关上了，而**没有任何东西会重新触发那次 effect**；
- 「生成中断：Unknown error」（`9a2a2eb`）——兜底文案写死在代码里；
- 规则输入框没有长度上限，用户写超了服务端才拒（`87b415d`）；
- 连点两下会把同一条编辑发两遍（`b8487c4`）；
- 一条消息的日期可以是任意字符串，包括「sometime last summer」（`4f635a0`）——
  周年扫描比的是月和日，于是这个周年**永远不会被提起**，也没有任何地方说日期读不出来；
- `limit: 2.5` 到了数据库（`82a1e4d`）——Postgres 拒绝整个查询，五百错误；
- 采集任务的持久化记录**丢了「被截断」的标记**（`5b41379`）——
  服务器重启之后，一个被截断的采集看起来是完整的。

**Python 工具（三个）里也有几处：**

- 飞书采集器把 **access token 的前二十个字符打印出来**（`7616f25`）——
  采集器的输出被服务端收进任务的日志，日志会展示给用户、也会落到磁盘上，
  于是一个能读别人消息的 token 的头**躺在不是秘密的文件里**；
- 钉钉采集器**在需要人按回车的那一刻死掉**（`4399955`）——服务端不给标准输入，
  `input()` 抛 EOFError，采集带着 traceback 停下；
- Slack 采集器**扔掉所有只有一个字的留言**（`addecfa`）——「好」「嗯」「k」都是人写的；
- `yt-dlp` **没有超时**（`635bd0b`）——连接卡住就一直卡着。

模型服务用的是**本地桩**（`scripts/live-stub-model.mjs`，说 OpenAI 的协议，包括流式），
所以 app 自己的代码路径（provider、请求体、解析）**原样跑过**；
**真的** provider 没有被调用过——这一条如实写在这里。

**这一批的后半段又补了九个（客户端与打包）：**

- **点一下背景就把告别拒了**（`85bf303`）：告别窗口背后的那层暗色，点一下**会被记成拒绝**——
  而那不是一次考虑过的「不用了」，是手滑，或者是点在了窗口后面的东西上。
  记录是**写进档案的**：这个分身被标成「已拒绝」，而且一阵子不会再被提起。
  明确的按钮和 ✕ 才是拒绝；背景只是一个出去的路。
- **同一个名字的两个文件是一行**（`47d11fa`）：那行的 key 是「文件名 + 时钟」，
  于是**同一毫秒里传的两个同名文件是同一行**，而第二个传完会把第一行删掉——
  第一个文件永远停在「上传中」。
- **档案页和毕业页把记忆截断了，不说**（`b0dff7d`）：服务端说了**一共有多少条**，
  而这两个页面没看：四百条记忆的分身只显示两百条，页面却写着「这些是里程碑」。
- **毕业页数的是查询的上限，不是日记**（`440044e`）：那个数字是列表的长度，
  而列表被查询的上限卡着——于是两百篇日记读起来像三十篇。
- **七句没人读的话，和看不出它们的测试**（`2398176`）：界面上的那几句在共享文案里
  也有一份，而**没有一份被读过**。查「没人读的条目」的测试也看不见它们：
  六个状态是通过模板取到的，豁免就落在了整个命名空间上。
  现在六个状态的 key 一个一个写出来，测试就能干活了。
- **换页时焦点不动**（`fbd2f08`）：单页导航换掉了页面，**焦点没动**——
  键盘用户按完链接，焦点还留在一个已经不存在的链接上，读屏软件还在念上一页。
- **问卷走到「标签」那一步，焦点丢了**（`4a55c20`）：别的步骤都有输入框，
  焦点到了那一步就落在输入框上；标签那一步没有——焦点留在用户刚按下的按钮上，
  而那个按钮已经没了。
- **图片的占位文字跟着旧语言走**（`d2d8e82`）：图片消息的正文是占位文字「[图片]」，
  而它被拿来和**当前语言**的副本比——于是用中文发图、后来把界面切成英文的人，
  在英文对话里看到自己图片下面写着「[图片]」。
- **容器用 root 跑，而且从不说自己是否健康**（`f36afbb`）：用 root 跑，
  app 里的一个错误就拿着整个容器的权限；而且它写的文件属于 root，
  挂进来的卷**运行容器的人写不了**。也没有 healthcheck——
  一个起来之后在报错的容器，在编排器和 `docker ps` 眼里和正常工作的容器一模一样。

**这一批的最后一段又补了六个（服务端、脚本、容器）：**

- **蒸馏把用户刚改的东西盖掉了**（`f8add1b`）：分身的字段是**一列**，
  所以写它就是「读一次、写一整列」——而别的每一条写它的路（修正、不完美档案、规则）
  **都拿着那把锁**。蒸馏没有：于是用户在蒸馏跑着的时候在编辑器里改了一句
  「她其实是这么说 X，不是 Y」，保存了、提示也说了「已保存」，一分钟后蒸馏结束，
  **把分身放回了改之前的样子**。修正日志留着记录，分身没有。
  现在读和写都在锁里；抽记忆那一步（一次模型调用，写的是记忆不是分身字段）
  在拿锁**之前**跑完，所以锁不会为了等一次模型调用而把编辑器挡住。
- **同一毫秒里写的消息永远读不到**（`2f7b178`）：翻页的游标只有时间——
  于是同一毫秒里的两条消息（回复和跟着发出去的那封信、采集器一口气写下的一批）
  **分在了边界两边**，而落在错那边的那几条**从来没有被读过**：
  这一页停在第一条，下一页从最后一条之后开始。id 是那个「谁在前面」的裁判。
- **实机脚本告诉通道它们是老版本**（`bba0d7a`）：版本号是写死的，
  而 app 早就不在那个版本了——于是实机脚本报的版本**不是它在测的版本**。
  现在版本来自 app 自己的 `package.json`。
- **`drizzle-kit push --force` 每次桌面启动都跑一遍**：
  危险在于它会**删掉** schema 里没有的列。这一条**现在有测试守着**——
  `server/schema-parity.test.ts` 断言 schema 与迁移的**列和索引完全一致**，
  所以 `push` 要删的东西，迁移里也一定没有。可是**这道闸只在 CI 里跑**，
  用户机器上没有。真要根治，桌面端应该只跑 `scripts/migrate.mjs`（带迁移日志的那种），
  而不是 `push`——那需要把迁移日志打进包里，是打包脚本的改动。
- **桌面包里没有 Python**、**`.app` 没有签名**、**发布没有校验和**、
  **CI 没有测真实的升级路径**、**GitHub Action 用的是可变的 tag**：
  都是分发与供应链的事，需要发布流程的重写，不是这一批能顺手带上的。
- **Windows 启动器（`.csproj`）里的版本号是手改的**：
  安装包脚本已经从 `package.json` 读版本了，`.csproj` 里那一份还在手改——
  改成读同一处需要改构建脚本的顺序，属于打包脚本的下一批。
- **Feishu 采集器把每个会话都列出来，没有上限也没有限速**：
  这会在一个大的企业空间里跑很久，并且把接口打到被限流。
  需要一个「只采集这些会话」的参数和一个退避策略——**采集器的行为设计**，不是 bug 修复。
- **飞书采集器的浏览器会退回到操作者自己的 Chrome profile**：
  Playwright 会在用户的**真实浏览器 profile 目录**上启动一个持久化上下文——
  如果 Chrome 正在跑，profile 是锁着的；如果没跑，采集器会**写进用户的真实 profile**。
  安全的默认值是给这个工具一个**自己的** profile 目录（用户第一次在里面登录一次），
  但那会改变现有的使用习惯（用户现在是「登录状态直接复用」），所以留到下一批一起决定。
- **采集器崩溃时临时文件留在磁盘上**：
  临时目录是在 `finally` 里清的，崩溃（SIGKILL）时清不掉。
  可以改成用系统临时目录（重启后由系统回收），也可以给采集器加一个启动时的清理——
  下一批。
- **几个低优先级的界面问题**：毕业页的日记总数就是查询上限、档案页与毕业页**静默截断**记忆、
  七条没人用的 `labels.imperfection.*` 文案、问卷的 chip 步骤丢焦点、
  上传的行 key 会撞、失败的行不能重试、换路由不换焦点、点背景会被记成一次拒绝、
  图片占位图不跟着语言走——都是**改起来不难、但每一处都要单独的界面判断**，
  这一批先修了里面最影响「用户对自己的数据被怎么对待」的那几处。
- **真的微信/飞书账号没有被驱动过**：飞书的回声修复有单元测试，但没有对着真的飞书事件流跑过；
  微信监控的失败处理只有**进程内**的验证。
- **模型服务是本地桩**：实机复验里模型服务是 `scripts/live-stub-model.mjs`（说 OpenAI 协议），
  app 自己的代码路径（provider、请求体、解析）原样跑过，但**真的** provider 没有被调用过。
- **子代理的清单之外没有再做一轮全量审计**：这一批覆盖的是七个只读子代理的报告；
  报告里没有提到的部分**没有重新审过**（下一批继续）。
