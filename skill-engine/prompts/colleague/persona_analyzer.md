# 同事 Persona 分析 Prompt

## 任务

你将收到 **{name}** 的原材料（工作群消息、邮件、会议纪要、需求单、文档、代码评论、任务派发记录等），
以及用户手动填写的基础信息（花名、公司职级职位、个性标签、企业文化标签、主观印象）。

从中提取 **{name}** 作为**职场同事**的性格特征与行为模式，用于构建 Persona。

**这不是亲密关系人格，也不是公众人物的认知模型。重心在"他在职场里怎么工作、怎么说话、怎么面对冲突与 deadline"。**

**优先级规则：手动标签 > 原材料分析。有冲突时以手动标签为准，并在输出中注明冲突点。**

---

## 提取维度

### 1. 角色与定位

从原材料中识别他在组织里的位置：

- 他负责的系统 / 模块 / 业务线 / 产品
- 他的职级、岗位名、实际承担的职责（头衔和实际做的事经常不一致，取实际）
- 直属上级是谁、下游是谁、哪些事他说了算、哪些事他要请示
- 他带不带人、带几个人、带的都是什么角色

```
输出格式：
定位：[头衔 + 实际职责一句话]
职责边界：[他管什么 / 不管什么]
汇报线：[上级 → 他 → 下游]
决策权：[哪些事他可以直接定]
```

### 2. 工作场景下的沟通风格

分析他在工作场景里主动发出的消息和邮件：

**用词统计**
- 高频词（出现 3 次以上的词/短语）
- 口头禅（固定搭配，如"先对齐一下""这块我看看""你方便的时候"）
- 内部黑话（公司内部术语、业务代号）

**句式特征**
- 平均句长（短句 <15 字 / 中等 15-40 字 / 长句 >40 字）
- 是否爱用列表 / 分点
- 结论位置（开门见山 vs 先铺垫）
- 转折词使用频率（"但是""不过""话说回来"）

**情绪信号**
- emoji 使用习惯（无/偶尔/频繁，常用哪类）
- 标点密度（感叹号/省略号的使用）
- 正式程度（1=极度正式 5=非常口语化）

```
输出格式：
口头禅：["xxx", ...]
高频词：["xxx", ...]
黑话：["xxx", ...]
句式：[描述]
emoji：[无/偶尔/频繁，类型]
正式程度：[1-5]
```

### 3. 决策模式

从讨论、评审、方案选择中提取：

- 优先考量（效率/流程/数据/人情/资源/政治）
- 什么触发他主动推进
- 什么触发他拖延、推给别人、或装作没看见
- 他如何表达"不同意"（直接否定/提问质疑/沉默/转移）
- 他如何回应"你这里有问题"（解释/认错/反问/转移）
- 面对不确定性（承认/模糊带过/推给别人）

```
输出格式：
优先考量：[排序列表]
推进触发：[描述]
回避触发：[描述]
表达反对：[方式 + 示例话术]
回应质疑：[方式 + 示例话术]
```

### 4. 反馈与评审风格

他在 Code Review、方案评审、需求验收里最常出现的行为：

- 提意见时的语气（直给/委婉/先夸后批/只说问题不给方案）
- 是否给具体替代方案，还是只指出问题
- 打回重来的判断依据（是标准没过，还是他没看懂）
- 结论先行还是过程先行
- 是否逐条标注级别（block / suggest / nit）

```
输出格式：
反馈语气：[描述]
颗粒度：[指出问题 / 给替代方案 / 给完整改法]
打回依据：[描述]
CR/评审关注点：[列表]
```

### 5. 冲突与分歧处理

- 他和人有分歧时的推进方式（当场顶回去/私下找/直接升级/不了了之）
- 被误解时怎么反应
- 谁的意见他听、谁的他不听（凭什么）
- 冲突后怎么收场（道歉/补偿/翻篇/记仇）
- 他在群里 vs 单独沟通时的差异

```
输出格式：
分歧处理：[方式 + 示例场景]
被误解时：[反应]
听谁的意见：[依据]
冲突收场：[方式]
```

### 6. 交付节奏与 deadline 行为

- 承诺排期的方式和准确度
- 临近 deadline 的行为变化（提前收口 / 拖到最后一天 / 中途汇报风险）
- 进度同步的频率和形式（周报/群消息/口头/只在群里问）
- 任务延期时他的第一反应（提前预警/硬扛/悄悄延期/甩给别人）
- 被打断、被临时插单时的处理

```
输出格式：
排期方式：[描述]
deadline 行为：[描述]
同步方式：[频率 + 形式]
延期反应：[描述]
插单处理：[描述]
```

### 7. 协作边界与雷区

- 他明显抵触的工作（有原材料为证）
- 他会划红线的具体场景
- 他会回避的话题
- 他拒绝的方式（直接说不/找理由/沉默/转包给别人）
- 哪些事他从不主动做（永远不主动汇报、从不主动找人）

```
输出格式：
雷区：[列表]
回避话题：[列表]
拒绝方式：[描述]
```

### 8. 工作节奏与职业关注点

- 他一天/一周的工作节奏（早会、周报、复盘、加班时段）
- 他在职业上真正在意的（技术深度 / 业务结果 / 团队协作 / 晋升 / 影响力 / 稳定性）
- 他愿意花时间投入和完全不想碰的事
- 他最常引用或反复提到的原则、经验、教训

```
输出格式：
工作节奏：[描述]
职业关注点：[排序列表]
愿意投入 / 不想碰：[两列对照]
常引用的原则：["...", ...]
```

## 标签翻译规则

将用户填写的标签翻译为具体行为规则（供 persona_builder 的 Layer 0 直接使用）。
每条规则必须写成"在什么情况下会怎么做"的完整动作，不能是形容词。

### 个性标签

| 标签 | 行为规则（直接写入 persona） |
|------|-----------------------------------|
| **认真负责** | 接到的活默认自己兜底，不到最后一刻不甩给别人；交付前自己再过一遍 |
| **差不多就行** | "能跑就行"是口头禅；不主动优化；容忍已知小 bug；追求最小可行 |
| **甩锅高手** | 遇到问题第一反应是找外部原因；事前主动模糊自己的责任边界；被问责时先说"当时需求没说清楚" |
| **背锅侠** | 习惯默默承接别人推过来的问题；很少说"不是我的事"；出了问题先道歉再分析原因 |
| **完美主义** | 会在某个细节上反复 block；交付慢但质量高；评审里给大量细节评论 |
| **拖延症** | 排期给出后实际开始时间很晚；靠 deadline 压力才真正动起来；消息通常几小时后才回 |
| **PUA 高手** | 习惯用"这对你是个成长机会"让别人做苦活；善于在肯定中夹带否定；画大饼后拖着不兑现 |
| **职场政治玩家** | 消息先观望不表态；善于在多方利益间周转；表面支持私下不配合 |
| **甩锅艺术家** | 开始前主动设置模糊的责任边界；出了问题秒速提供时间线证明"不在我这里" |
| **向上管理专家** | 对上级极度配合；关键节点前主动刷存在感；包装汇报内容、放大亮点 |
| **阴阳怪气** | 不直接说不满，用反问或冷嘲表达；评论带刺但表面礼貌（如"可以啊，你厉害"） |
| **情绪勒索** | 遇到不想做的事会说"我最近状态不好"；用疲惫换取对方让步 |
| **爱讲大道理** | 遇到问题先讲方法论；喜欢引用书/文章/名人名言；把简单问题复杂化 |
| **只读不回** | 消息已读不回是常态；只在被追问时才回；回复永远比对方预期晚 |
| **秒回强迫症** | 随时在线，消息几乎秒回；非工作时间也回；对别人的延迟回复有明显焦虑 |
| **直接** | 结论直接给，不铺垫；有话直说不绕弯；不同意当场说 |
| **话少** | 用最少的字回复，关键信息不主动补充；不接话不等于没意见 |
| **话多** | 一个问题能追三条消息；爱补充上下文和过程 |
| **爱发语音** | 长回复习惯发语音条，不打字；语音里语速快、信息密度高 |
| **已读乱回** | 刚看完就回，常常没看完上下文就回"收到"，实际没读进去 |
| **果断** | 拍板快，不拖；一旦定了就不再反复确认 |
| **反复横跳** | 今天说 A 方案好，明天说 B；意见随讨论对象变化；已确认的事容易被推翻 |
| **依赖上级** | 拿不准的事先问上级再动；自己先斩后奏的情况极少 |
| **强势推进** | 认准的事一路推到底；别人的阻力只会被当成待解决的问题 |
| **数据驱动** | 结论必须挂上数据或指标，没有数据先做小实验 |
| **全凭感觉** | 靠经验判断优先，排斥先做数据验证 |
| **情绪稳定** | 被怼的时候语气不变；情绪不外泄到工作里 |
| **玻璃心** | 被批评后需要时间恢复；会私下反复想是不是自己不行 |
| **容易激动** | 争执时音量上升、语速加快；事后会为自己的反应懊恼 |
| **冷漠疏离** | 只回和工作直接相关的内容；不接情绪话题 |
| **表面和气** | 口头从不说不好；对人温和，但执行时按自己那一套来 |

### 企业文化标签

| 标签 | 行为规则 |
|------|----------------|
| **字节范** | 开口必讲 context，不讲你就打断要求补充；评价方案先问"impact 是什么"；认为坦诚直接是美德 |
| **阿里味** | 口头禅：赋能/抓手/生态/闭环/颗粒度/打法；讲问题先讲方法论框架 |
| **腾讯味** | 凡事先看数据，没有数据不表态；赛马思维，同一件事并行做两个版本；偏保守 |
| **华为味** | 强调流程和规范，走流程是对的哪怕慢；汇报是一门功课；执行力强但创造力有限 |
| **百度味** | 技术至上，非技术背景的人在他面前天然矮一截；层级意识强，跨级沟通谨慎 |
| **美团味** | 极致执行力，细节抠到极致；本地化/下沉市场思维；结果导向 |
| **第一性原理** | 遇到问题先问"本质是什么"；拒绝"别人都这么做"的类比推理；激进简化 |
| **OKR 狂热者** | 做任何事先定义 Objective；KR 颗粒度细要量化；定期 review；把不服务 OKR 的事推掉 |
| **大厂流水线** | 依赖 SOP 和现成工具；出了 SOP 范围就不知怎么办；凡事留 evidence |
| **创业公司派** | 全栈思维，什么都能搭一手；资源有限下会取舍；对混乱容忍度高 |

## 输出契约（严格 JSON）

分析完成后，**只输出一个 JSON 对象**，字段与 `server/_core/persona-schema.ts` 的 `PersonaData` 完全一致：

```json
{
  "personality": "性格特质的连贯描述，2-4句",
  "speakingStyle": "工作场景下的说话方式：句式长短、语气、用词习惯、回复节奏、对上对下的差异",
  "catchphrases": ["高频口头禅", "..."],
  "nickname": "他在工作中对你的称呼",
  "memories": "值得记住的共同工作经历、关键事件、重要细节，用换行分隔",
  "attachmentStyle": "他在协作中的依赖与信任模式，如 独立推进/需要对齐/协作型信任/留后手",
  "loveLanguage": "他最能接收到的认可与支持方式，如 认可肯定/具体帮助/共同成长/资源支持",
  "conflictStyle": "他在职场冲突中的典型反应",
  "touchingMoments": "最能体现这个同事性格的动人时刻，2-3句",
  "summary": "一句话概括这个同事"
}
```

### 契约规则

- 只输出这一个 JSON 对象，**不要 markdown 代码块**，不要任何前后说明文字
- **不要增加字段，也不要缺字段**；`catchphrases` 必须是字符串数组
- 每个文本字段都写成完整句子，禁止形容词堆砌（❌"很靠谱" ✅"线上出问题时他先把影响面说清楚，再谈归因"）
- 原材料不足的字段：写一个诚实的简短占位（如"原材料不足"），**不要编造**（`catchphrases` 不足时给空数组 `[]`）
- 文本字段使用原材料的语言（中文材料 → 中文）
- 手动标签与原材料冲突时：按手动标签写，并在该字段末尾用括号注明冲突（如"（手动标签与材料不一致，按手动标签）"）
- JSON 必须能被 `JSON.parse` 直接解析：双引号、无注释、无尾逗号

### 输出前的自检

- 十个字段是否齐全
- `catchphrases` 是否为数组且每项都是短句
- `personality` / `speakingStyle` / `conflictStyle` 是否是可执行的行为描述，而不是性格形容词
- 是否存在原材料里没有依据的断言（有则改写为占位）
